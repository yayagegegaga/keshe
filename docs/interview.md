# 面试讲解材料

## 30 秒项目介绍

这是一个校园流浪动物救助与领养管理系统，面向校园社区、救助站和公益组织。系统围绕流浪动物救助、志愿者任务、领养审核、回访和通知形成完整业务闭环，后端使用 Spring Boot、Spring Security、JWT、MyBatis-Plus、MySQL 和 Redis，前端使用 Vue 3 和 Element Plus。

## 1 分钟项目介绍

项目采用单体后端 + 前后端分离架构，不做微服务或分布式包装。后端重点实现了用户认证、RBAC 权限控制、业务状态流转、事务一致性、审核日志、分页查询、文件上传、Redis 首页统计缓存和统一异常处理。核心流程包括用户提交救助线索，管理员审核并生成工单，志愿者处理工单，动物进入领养流程，用户提交领养申请，管理员推进初审、面谈、试养和领养成功，最后形成回访记录和站内通知。

## 3 分钟项目介绍

这个项目不是简单的动物 CRUD，而是围绕校园流浪动物救助场景设计的一套协同管理平台。系统角色包括普通用户、志愿者、救助站管理员和系统管理员。普通用户可以提交救助线索、申请领养、查看自己的申请、通知和回访；志愿者可以处理分配给自己的工单并领取任务；管理员可以审核线索、创建和分配工单、管理动物档案、审核领养申请、发布任务、创建回访记录。

后端设计上，我把 Controller 控制在请求转发和统一返回，核心业务规则放在 Service 层。例如救助工单状态只允许 `WAIT_ASSIGN -> ASSIGNED -> PROCESSING -> WAIT_CONFIRM -> CLOSED`，非法流转会被 Service 拦截。领养申请状态也有明确状态机，并且领养成功时用事务同时更新申请状态、动物状态、关闭其他未结束申请并写入审核日志。志愿者任务领取使用条件更新 `WHERE status = 'WAIT_CLAIM'`，避免重复领取。

系统还使用 Redis 缓存首页统计，目的只是减少重复统计查询数据库；文件上传采用本地存储，校验后缀、大小、业务类型并保存文件记录；权限使用 Spring Security + JWT + RBAC，普通用户只能操作自己的数据，管理员可以管理全局数据。

## 核心业务流程

1. 救助流程：用户提交线索 -> 管理员审核 -> 生成工单 -> 分配志愿者 -> 志愿者处理 -> 管理员关闭。
2. 志愿任务流程：管理员发布任务 -> 志愿者领取 -> 提交完成记录 -> 管理员审核。
3. 领养流程：用户申请 -> 初审 -> 面谈 -> 试养 -> 领养成功 -> 回访。
4. 配套能力：通知、文件上传、首页统计缓存、接口文档。

## 主要负责的后端模块

- 认证与 RBAC 权限控制
- 动物档案管理
- 救助线索和救助工单状态流转
- 志愿者任务领取和审核
- 领养申请状态机和事务一致性
- 回访记录、通知、文件上传和统计缓存
- SQL 表设计和初始化数据

## 最有价值的后端设计点

- 用枚举统一管理状态和类型，避免业务代码散落硬编码。
- Service 层集中状态流转校验，Controller 不写复杂业务。
- 关键业务使用事务保证一致性。
- 工单和领养申请都有日志表，方便追踪流程。
- 志愿任务领取通过条件更新防重复。
- Redis 缓存首页统计，但不夸大为高并发设计。
- 文件上传做后缀、大小、路径和业务类型校验。

## 状态流转怎么做

在 Service 层维护允许流转的状态表，例如工单只允许从待分配到已分配、处理中、待确认、已关闭。每次状态变化前调用统一校验方法，非法状态直接抛业务异常。领养申请也采用同样方式控制 `PENDING`、`FIRST_APPROVED`、`INTERVIEWING`、`TRIAL`、`SUCCESS` 等状态。

## 事务一致性用在哪

领养成功是最典型的事务场景：需要把当前申请改为 `SUCCESS`，把动物改为 `ADOPTED`，关闭该动物其他未结束申请，并写入审核日志。这些操作必须全部成功或全部回滚。工单状态变化和日志写入、任务完成和完成记录写入也使用事务。

## Redis 为什么用

Redis 用于两个轻量场景：登录 token 缓存和首页统计缓存。首页统计涉及多张表计数，实时性要求不高，所以缓存 5 分钟，减少首页反复刷新时的数据库统计查询。Redis 不可用时统计接口会降级查数据库。

## 防重复领取怎么做

志愿者领取任务时使用条件更新：

```sql
UPDATE volunteer_task
SET status = 'CLAIMED', volunteer_id = ?
WHERE id = ? AND status = 'WAIT_CLAIM'
```

如果影响行数为 0，说明任务已经被领取或状态变化，后端返回业务异常。

## 权限控制怎么做

使用 Spring Security + JWT。登录后生成 token，后续请求通过 `Authorization: Bearer <token>` 认证。角色包括 `USER`、`VOLUNTEER`、`ADMIN`、`SUPER_ADMIN`。管理员接口用 `@PreAuthorize` 控制，用户自己的数据在 Service 层做归属校验。

## 文件上传怎么保证安全

- 禁止空文件
- 限制后缀：jpg、jpeg、png、gif、webp、pdf
- 限制大小：默认 10MB
- 使用 UUID 生成存储名
- 按日期目录保存
- 清洗原始文件名并校验路径归一化
- 前端只返回 URL 等安全字段，不暴露服务器物理路径

## 遇到的问题和解决方式

1. 登录异常排查：最初接口只返回“认证服务异常”，最终通过日志定位到 MySQL `root/root` 认证失败，同时 Redis 未启动。处理方式是给认证异常增加真实日志，并把 `application-dev.yml` 改成环境变量可覆盖。
2. 文件记录权限：最初只有管理员可查文件，后来补充 `/api/files/my` 和删除归属校验，普通用户只能操作自己的文件。
3. 统计缓存用户数据串用风险：统计里加入未读通知后，缓存 key 从全局 key 调整为 `statistics:overview:{userId}`。
